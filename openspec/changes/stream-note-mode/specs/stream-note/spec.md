## ADDED Requirements

### Requirement: `mode` 設定と検証

テンプレートプレースホルダ（`{...}`）を含むパスを持つ登録ノートは、`mode` フィールドで `periodic`（既定）または `stream` を指定できなければならない（SHALL）。`mode: stream` はプレースホルダを含まないパス、またはプレースホルダがファイル名以外の要素（ディレクトリ部分）に含まれるパスに対しては設定エラーとしなければならない（SHALL）。`mode` が省略された既存設定の挙動は一切変わってはならない（MUST NOT）。

#### Scenario: mode 省略時は periodic として動作する

- **WHEN** `path: ~/Notes/daily/{yyyy-MM-dd}.md` のノートが `mode` 指定なしで登録されている
- **THEN** 従来の periodic note と完全に同じ挙動をする（現在時刻解決・ロールオーバー含む）

#### Scenario: プレースホルダの無いパスに stream を指定した場合

- **WHEN** `path: ~/Notes/memo.md` のノートに `mode: stream` が指定されている
- **THEN** 設定エラーとして報告され、ノートは登録されない

#### Scenario: rollover_delay との併用

- **WHEN** `mode: stream` のノートに `rollover_delay: 4h` が指定されている
- **THEN** 警告がログに出力され、`rollover_delay` は無視される

### Requirement: ファイル名ワイルドカード

stream モードのテンプレートは、ファイル名要素に単一の `*` ワイルドカードを含められなければならない（SHALL）。`*` は0文字以上の任意の文字列に一致する。複数の `*`、ディレクトリ要素内の `*`、および periodic モードでの `*` は設定エラーとしなければならない（SHALL）。テンプレートからファイルを新規作成する場合、`*` は空文字列として解決する（SHALL）。

#### Scenario: スラッグ付きファイルの一致

- **WHEN** テンプレートが `~/notes/claude/{yyyy-MM-dd-HHmmss}-*.md` で、ディレクトリに `2026-07-13-091654-llm-ops.md` と `memo.md` が存在する
- **THEN** `2026-07-13-091654-llm-ops.md` は一致し、`memo.md` は一致しない

#### Scenario: periodic モードでのワイルドカード

- **WHEN** `mode` 省略（periodic）のノートのパスに `*` が含まれている
- **THEN** 設定エラーとして報告され、ノートは登録されない

### Requirement: 現在ファイルの解決（Latest）

stream モードのノートは、起動時・`toggle` ホットキー・Latest ボタンのいずれにおいても、テンプレートに一致するファイル群の辞書順末尾（latest）を表示しなければならない（SHALL）。periodic モードの Today ボタンは stream モードでは Latest ボタンとして表示されなければならない（SHALL）。一致ファイルが存在しない場合は、テンプレートを現在時刻で解決したパスに空ファイルを作成して表示する（SHALL）。

#### Scenario: 起動時に latest を表示する

- **WHEN** ディレクトリに `2026-07-13-090000.md` と `2026-07-13-100000.md` が存在する状態で stream note を開く
- **THEN** `2026-07-13-100000.md` が表示される

#### Scenario: 一致ファイルが無い場合

- **WHEN** ディレクトリにテンプレート一致ファイルが1件も無い状態で stream note を開く
- **THEN** 現在時刻で解決したファイル名の空ファイルが作成され、表示される

### Requirement: ディレクトリ監視と follow 動作

stream モードのノートは、テンプレートの親ディレクトリを監視し、新しい一致ファイルの出現を検知しなければならない（SHALL）。ウィンドウが表示中かつ latest ファイルを表示している場合に限り、新しい latest へ自動遷移しなければならない（SHALL）。ユーザーが過去のファイルを表示している間、またはウィンドウが非表示の間は、自動遷移してはならない（MUST NOT）。この場合はナビゲーションボタンの活性状態のみを更新する（SHALL）。

#### Scenario: latest 表示中に新規ファイルが出現する

- **WHEN** `2026-07-13-100000.md`（latest）を表示中に、外部プロセスが `2026-07-13-110000.md` を作成する
- **THEN** 表示が `2026-07-13-110000.md` に自動的に切り替わる

#### Scenario: 過去のファイルを閲覧中に新規ファイルが出現する

- **WHEN** ◀ で `2026-07-13-090000.md` に戻って閲覧中に、外部プロセスが新しいファイルを作成する
- **THEN** 表示は切り替わらず、▶ ボタンで新しいファイルまで進める状態になる

#### Scenario: テンプレートに一致しないファイルの出現

- **WHEN** 監視中のディレクトリにテンプレートに一致しない名前のファイルが作成される
- **THEN** 表示・ナビゲーションのいずれにも影響しない

### Requirement: ロールオーバーの非適用

stream モードのノートに対して、periodic note のロールオーバータイマー（現在時刻から解決したパスへの定期的な切り替え）を適用してはならない（MUST NOT）。

#### Scenario: 時間経過による自動切り替えが起きない

- **WHEN** stream note で `2026-07-13-100000.md` を表示したまま数分間放置する
- **THEN** 新しい一致ファイルが出現しない限り、表示ファイルは変化せず、空ファイルも作成されない

### Requirement: ナビゲーション

stream モードの ◀/▶ ナビゲーションは periodic モードと同一の仕組み（押下ごとのディレクトリ再走査＋辞書順ソート）で動作しなければならない（SHALL）。外部プロセスが作成したファイルは、アプリの再起動なしにナビゲーション対象へ含まれなければならない（SHALL）。

#### Scenario: 外部プロセス作成ファイルへの前後移動

- **WHEN** アプリ起動後に外部プロセスが複数の一致ファイルを作成し、ユーザーが ◀/▶ を押す
- **THEN** 作成されたすべての一致ファイルを時系列順（辞書順）に行き来できる

### Requirement: `create` ホットキー（クイックキャプチャ）

stream モードのノートに `create` ホットキーが設定されている場合、押下時にテンプレートを現在時刻で解決した新規ファイルを作成し、それを latest として表示しなければならない（SHALL）。

#### Scenario: 手動エントリの追加

- **WHEN** stream note の `create` ホットキーを押す
- **THEN** 現在時刻のファイル名で空ファイルが作成され、編集可能な状態で表示される

### Requirement: 表示中ファイル削除時のフォールバック

表示中のファイルが外部から削除された場合、stream モードのノートは残存する一致ファイルの latest へ遷移しなければならない（SHALL）。残存ファイルが無い場合は、現在時刻で解決した新規ファイルを作成して表示する（SHALL）。

#### Scenario: 表示中ファイルの削除

- **WHEN** 表示中の `2026-07-13-110000.md` が外部から削除され、`2026-07-13-100000.md` が残存している
- **THEN** 表示が `2026-07-13-100000.md` に切り替わる
